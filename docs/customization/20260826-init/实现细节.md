# Horizon 二开实现细节

> 本文档记录各二开功能的**实现细节**（落点、数据流、hook 位置）。
> 开发纪律（分支/同步/标记规范）见根目录 [`CLAUDE.md`](../../../CLAUDE.md)，本文档不重复。

---

## 目录结构（`src/custom/` —— 上游永不触碰）

```
src/custom/
  __init__.py
  config.py         # 二开配置的 pydantic 模型 + 加载器（读 data/custom.json + 环境变量）
  registry.py       # 自定义 scraper 注册表
  scrapers/         # 自定义 scraper 子类（继承上游 BaseScraper，source_type 伪装 rss）
  illustrator.py    # 文生图：文本LLM生prompt → OpenAI兼容图像API → 落盘 data/images/
  publisher.py      # 发布器：日报Markdown+图片URL → POST 自研博客API（日期slug幂等）
```

## 上游侵入点总览（5 处成对标记）

全部带 `HORIZON-CUSTOM` 标记，位于 `src/orchestrator.py`：

| 场景标签 | 位置 | 动作 |
|---|---|---|
| `imports` | 顶部 | import custom hooks |
| `custom-sources` | `fetch_all_sources()` | 把自定义 scraper 任务并入 `tasks` |
| `illustrations` | `run()`，enrich 之后 / lang 循环前 | 给 top N 生图，返回 anchor→url 映射 |
| `illustrations` | `run()`，`generate_summary` 之后 | 按锚点后处理把 `![](url)` 插进 summary |
| `publish` | `run()`，lang 循环内末尾 | 发布 zh 日报到博客 |

> 配图占两处：生图（语言无关，循环前一次）与插图（每种语言各插一次）。图片**不写进 item 数据**——`_format_item` 会转义 Markdown——而是对最终 summary 字符串做后处理插入。

## 1. 自定义 LLM Endpoint —— 用配置，别写代码

上游 `AIConfig` 已原生支持自定义 endpoint。**只要你的 LLM 服务是 OpenAI 兼容协议**（one-api / new-api / vLLM / 中转站等），在 `data/config.json` 里配置即可，**零代码改动**：

```json
{
  "ai": {
    "provider": "openai",
    "base_url": "https://your-endpoint/v1",
    "api_key_env": "YOUR_LLM_API_KEY",
    "model": "your-model"
  }
}
```

- 真值放 `.env` / 环境变量（`api_key_env` 只写变量名）。
- 只有当 endpoint 是**非 OpenAI/Anthropic 兼容的私有协议**时，才需要在 `src/custom/` 写 `AIClient` 子类——目前不需要。

## 2. 自定义源

- 代码：`src/custom/scrapers/` 下写 scraper，**继承上游 `src/scrapers/base.py::BaseScraper`**。
- 注册：`src/custom/registry.py` 导出自定义 scraper 工厂列表。
- **`source_type` 伪装成 `SourceType.RSS`**：上游 `ContentItem.source_type` 是固定枚举且 `extra="forbid"`，自定义源不新增枚举成员；真实来源身份塞进 `ContentItem.metadata`（如 `metadata["custom_source"]="xxx"`）。这样 `models.py` 一个字都不用改，自定义源自动走完下游去重/打分/profile 全流程。
- Hook 位置：`src/orchestrator.py::fetch_all_sources()` 里加一行 `HORIZON-CUSTOM(source)` hook，把自定义 scraper 的抓取任务并入 `tasks`。

## 3. 文章配图（AI 文生图）

- 代码：`src/custom/illustrator.py`。
- 触发点：`src/orchestrator.py::run()` 中，**`enrich_items()` 之后、`generate_summary()` 之前**，加一行 `HORIZON-CUSTOM(image)` hook。
- 对象：`important_items` 的 **top N**（配置 `illustrate_top_n`，默认 `3`）。
- 流程：
  1. 用**文本 LLM**（复用上游 `src/ai/client.py::AIClient`，走已配置的文本 provider）为报道生成一段"绘画提示词"。
  2. 经**图像 provider 抽象层**（`src/custom/image_providers.py`）出图，按 `image_provider` 字段选实现。
  3. 图片落盘到 `data/images/YYYY-MM-DD/`。
  4. 后处理把图片 `![](url)` 按锚点插进最终 summary（**不能写进 item 数据**，会被上游 `_format_item` 的 `_escape_markdown` 转义）。
- **图像 provider 抽象层**（方便切换模型，`image_provider` 字段）：
  - `openai`：OpenAI 兼容 `/v1/images/generations`（DALL·E、多数中转站）。返回 b64 或 url。
  - `dashscope`：阿里云百炼文生图（`qwen-image-3.0` 系列）。**同步调用** POST `services/aigc/multimodal-generation/generation`（不带 `X-DashScope-Async` 头，请求阻塞到出图完成）→ 从 `output.choices[].message.content[].image` 取图片 URL 下载。注意 OSS URL **24h 过期**，落盘即时化解。`image_size` 用 `宽*高` 格式（如 `1024*1024`），provider 内会把 `1024x1024` 自动归一化为 `*` 形式。
  - 新增 provider：在 `image_providers.py` 加继承 `ImageProvider` 的类 + 登记 `PROVIDER_REGISTRY`。
- **失败静默降级**：任一步失败 → 该报道无图，文章照常生成与上传，仅记 `warning`。**绝不因配图失败中断每日任务。**
- 清理：`data/images/` 下超过 `image_retention_days`（默认 `30`）天的目录，定时任务顺手清理。
- 注意：上游对**图像生成零支持**，图像客户端完全自建于 `image_providers.py`（文本 LLM 的 `base_url` 机制只服务文本，不要混用）。

## 4. 文章上传（发布到自研博客）

- 代码：`src/custom/publisher.py`。
- 触发点：`src/orchestrator.py::run()` 中，**`generate_summary()` / 保存 summary 之后**，加一行 `HORIZON-CUSTOM(publish)` hook。
- 目标：**自研博客 API**（契约双方约定，用最舒服的 JSON）。
- 粒度：**一天一篇 post**，整份日报 Markdown。
- 幂等：请求参数带 **slug（用日期，如 `2026-08-24`）**，同日覆盖，重复运行不产生重复文章。
- 图片交接：Markdown 内图片为**完整公网 URL**；博客端负责异步拉取转存图床 + 生命周期管理（删文章自动删图床）。**本项目不碰图床。**
- 网络形态（Docker 内网 `http://blog:port` vs 公网 URL）运行时由配置决定，代码不写死拓扑。

## 二开配置涵盖项（`data/custom.json`）

- 自定义源列表
- `illustrate_top_n`（配图数量，默认 3）
- 图像 API `base_url` / `model`
- 博客 API 地址 / slug 规则
- `image_retention_days`（图片本地保留天数，默认 30）

密钥类（图像 API key、博客 API token）走环境变量，配置里只写变量名。
